# BRAIN_PLAN — Pocket AI Assistant (phone-first, brain-inspired)

**Date:** 2026-06-04 · **Companion to:** `AGENT_RESEARCH_2026-06-04.md`
**Thesis:** On-device personal AI assistant **for the masses** — privacy-first, offline-capable. **The phone is the WHOLE brain; the hub is an OPTIONAL accelerator** (graceful degradation, never required). Differentiator = the *nervous system* (memory, modes, consolidation, embodiment, ru/kz), NOT raw model size.

---

## 0. Constraints (mass-market)
- Runs standalone on a phone; **no mandatory hub** (most users don't have one).
- **Android + iOS**; RAM 6–12 GB; must work on cheap phones.
- Languages: **ru + en ONLY** (Qwen3.5-4B natively strong on both; e5-small encoder covers both). **Kazakh DROPPED 2026-06-04** (product call) — not a driver.
- **PERSONALIZATION MODEL (mass clients by hobby) — decided 2026-06-04:** per-user/per-hobby personalization = **MEMORY + KNOWLEDGE PACKS (RAG), NOT per-user LoRA adapters** (training-per-user doesn't scale; packs update instantly + compose). 3 layers: (1) **shared** = base 4B + `core` + `creative` (everyone); (2) **per-hobby = curated RAG knowledge pack** (~100 packs cover most hobbies; built once in hours; "update assistant by hobby" = push/update a pack, zero retraining; user with N hobbies = N packs, compose); (3) **per-user = personal memory** (Memory Plant, grows automatically). Hobby needing a *skill/style* → rare shared style-adapter; hobby needing *capability* (chess/trading) → tool, not adapter. ⇒ Memory Plant IS the personalization engine; the model stays shared.
- Offline-first, privacy-first (on-device inference + on-device memory).
- **NO USER HUB (decided 2026-06-04):** masses don't own a Mac/PC/server → the WHOLE product runs on the phone (model + adapters + tools + local memory + cached hobby packs), fully self-contained. Distinguish: **"hub" = user hardware = NOT assumed** vs **"cloud backend" = OUR servers = OPTIONAL** (online-only, with consent, graceful-offline) used only for online extras (e.g. building/refreshing hobby packs). Hard reasoning/math → on-device TOOLS cover most (4B≈9B on everyday); rare super-hard = optional cloud, never required. Hobby packs can even be PHONE-BUILT (phone searches + own 4B curates → local pack) → zero backend dependency for MVP.

## 1. Base decision (MEASURED, not guessed)
Phone base = **Qwen3.5-4B** (dense, hybrid Gated-DeltaNet, multimodal, 201 langs, Apache 2.0).
Our eval (MLX 4-bit, M3 Pro): **ru 5/5, kz 2/3 bare, 2.53 GB, 44 tok/s** — beats *tuned* LFM2.5-v8 on ru/kz at **half the RAM**. And **4B ≈ 9B on everyday + agentic** (TAU2 ~tie); 9B only wins hard math/code.

**Hardware tiering:**
| Tier | Device | Base |
|---|---|---|

## 2. Brain mapping → our stack
| Brain | Function | Mechanism | Our piece |
|---|---|---|---|
| Neocortex | slow semantic memory | frozen weights | Qwen3.5-4B (frozen) |
| Hippocampus | fast episodic memory | external store / RAG | **Memory Plant** (local) |
| Sleep consolidation | episodic → semantic | periodic LoRA on frequent facts | `memory` adapter |
| Prefrontal cortex | working memory, deliberation | context/KV + System-2 | dial=high (`<think>`) |
| Cerebellum | fast automatized skills | distilled fast path | dial=low |
| DMN ↔ ECN | divergent ↔ convergent (creativity) | mode switch + decode | `creative` ↔ `core` adapters |
| ACC / basal ganglia | conflict detect, action select | router + auto-dial trigger | gateway |
| Specialized cortex | vision/lang/motor | tower + skill adapters | vision (built-in) + LoRA |
| Corpus callosum / global workspace | integration, broadcast | blackboard / gateway | local gateway (+ optional hub) |
| Sensorimotor loop | perception–action | agent + tools | devices (glasses/watch/home) |

## 3. Architecture (phone-first)
- **Frozen cortex:** one resident Qwen3.5-4B (~2.5 GB).
- **"Hemispheres"/skills = LoRA adapters** (hot-swap, ~0 extra RAM): `core` (analytical: dial+identity+tool-call+ru), `creative` (right hemisphere: divergent), `kz`, `domain`.
- **Hippocampus:** Memory Plant on-device (retrieve before turn, ingest after). Sync optional/cross-device.
- **Mode switching:** auto-dial (System-1/2) **and** analytical↔creative (DMN↔ECN), with a **divergent→convergent** pipeline for open-ended tasks (creative proposes → analytical evaluates → final).
- **Gateway = corpus callosum:** picks adapter/mode; **OPTIONALLY** escalates hard queries to a hub; **always has a local fallback**; hosts a small blackboard (memories + tool results + partial outputs).
- **Embodied loop:** tool-call → act → observe → log outcome to Memory Plant → (later) learn.

## 4. The creative "right hemisphere" — detail
**= a `creative` LoRA adapter + creative decoding (temp↑, top-p↑) on the SAME 4B**, NOT a second model.
- Why not a small 2nd model: a 1–2B model is dumber and costs +0.6–1.5 GB RAM; a creative *adapter* is smarter (it's the 4B) and ~30 MB. Creativity is mostly **decoding + training data**, not separate weights.
- Brain-true pattern: **DMN (divergent ideation) ↔ ECN (convergent evaluation)**, dynamic switching — not two parallel brains.
- A genuinely separate creative model is justified **only on the hub** (where RAM is free), for deep/parallel creative dialogue. Not for the mass phone path.

## 5. Phases (build order)
- **Phase 0 — Cortex skills:** tune `core` adapter (dial+identity+tool-call+ru-replay) on Qwen3.5-4B. *(prereq; recipe ready from LFM2 v8)*
- **Phase 1 — Hippocampus ⭐:** memory middleware — `mp_semantic_search`/`mp_recall_fact` before turn (inject top-K), `mp_ingest_message` after. Cross-device via shared Memory Plant. *(buildable now)*
- **Phase 2 — Auto System-1/2:** uncertainty/conflict monitor (entropy/logprob margin or rule) sets SYS_LOW/HIGH automatically. *(v1 heuristic now)*
- **Phase 2.5 — Creative hemisphere:** `creative` LoRA + creative decoding; mode router analytical↔creative + diverge→converge pipeline.
- **Phase 3 — Sleep consolidation:** scheduled job folds frequent Memory Plant facts (access ≥3×) into a `memory` LoRA. CLS-safe: frozen base + ru-replay → no catastrophic forgetting.
- **Phase 4 — Global-workspace gateway:** FastAPI service; adapter hot-swap/fuse; blackboard; **hub OPTIONAL** with local fallback; difficulty/lang routing. ⚠️ MLX multiturn cache bug #980 → single-shot per turn or llama.cpp serving.
- **Phase 5 — Embodied loop:** tool-call loop + outcome logging to Memory Plant; later DPO/SFT on successful traces.
- **Cross-cutting — Skill consolidation:** continuously distill successful `<think>` (System-2) solutions into the fast no-think path (System-1).

## 6. Runtimes / cross-platform (for the masses)
- **iOS:** MLX-Swift or llama.cpp.
- **Android:** llama.cpp / MLC-LLM / Google AI Edge (MediaPipe).
- **Fit cheap phones — RAM levers MEASURED on our `Qwen3.5-4B-MLX-4bit` (2026-06-04).** Model = **2.83 GB** split: text-LM (attn+mlp) **1.87 GB** + vision-башня **0.62 GB** + embeddings (TIED) **0.33 GB**.
  - **⭐ #1 — Text-only vision-unload = −0.62 GB, ~free.** 4B is multimodal; the `vision_tower.*` (297 tensors) only fires on image input. **Lazy-load:** default text-only (**2.20 GB**), load vision on-demand when a picture arrives (camera/glasses/screenshot), optionally unload after. Engine: llama.cpp `--no-mmproj`; MLX = skip loading `vision_tower.*`. Common case (text/voice) saves 0.62 GB with zero model surgery. **Biggest lever.**
  - **vocab-trim ru/en — SMALL here (~0.12–0.23 GB), low ROI.** Script-trim (keep Latin+Cyrillic) = keep **66.3%** / cut **33.7%** (CJK 23.7 + Arabic 3.5 + Hangul 2.7 + SE-Asian 2.4 + Indic/Hebrew/Geo/Arm), but embeddings are only 0.33 GB → save **~0.12 GB**; aggressive corpus-trim (~90k tok) → **~0.23 GB**. ⚠️ The report's "−0.68 GB" was the **9B (untied)** — most of it was *tying*, which **our 4B already has** (`tie_word_embeddings:True`). And kz lives in the kept Cyrillic block → "en+ru" vs "en+ru+kz" give the **same** script-trim %. Trim needs embedding/lm_head surgery + tokenizer remap + heal + adapter re-check → do **only** for a low-end squeeze, and then corpus-trim, not script-trim. Non-RAM bonuses: slightly faster decode (smaller lm_head softmax), smaller download.
  - **Combo:** 2.83 → **2.20** (vision off) → **~2.0 GB** (+ corpus-trim) = comfortable on 6 GB phones. Then drop to 3-bit/2B only for the lowest tier (3-bit on dense-4B = real quality hit, see ROADMAP).

## 12. PRODUCT PRINCIPLES / guardrails (endorsed 2026-06-04 — the soul, not optional)
1. **Privacy = the killer feature.** All behavior observation stays ON-DEVICE in local memory; transparent; consent-based; user can SEE and DELETE everything the assistant knows. A private life-coach that never leaks. (Differentiator, not just a constraint.)
2. **Proactivity with restraint.** Few, well-timed, genuinely-useful nudges — over-suggesting kills trust. Rather rare-and-precise than chatty.
3. **Gentle insights.** Correlation ≠ causation → phrase as soft suggestions ("заметил, возможно…"), never commands or over-confident claims.
4. **Optimize ONLY to the user's own goals.** Don't impose; requires explicit goals + consent + user control over what's optimized.
5. **Honest about the 4B ceiling.** Pattern-noticing + sensible suggestions = in reach; deep psychological coaching = limited — don't over-promise.
